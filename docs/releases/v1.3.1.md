# Draugr Time 1.3.1

Fix tracking after the system clock moves backwards, including after booting
Windows and then Linux on a dual-boot computer.
**Draugr Time is in active development:** the interface and features are still evolving.

## Fixes

- Tracking no longer stays stuck with "heartbeat timestamp precedes the last event
  in its bucket" after a backwards clock adjustment of at least three seconds.
  This also recovers an existing database whose latest samples are in the future.
- Before replacing conflicting native tracking samples, Draugr Time saves a full,
  verified database copy beside the active database as `clock-rollback-*.sqlite`.
  Samples crossing the corrected time are clipped; later native samples remain
  available in the copy. Manual tags, rules and imported web events are unchanged.
  If the backup cannot be created, the conflicting history is left intact and an
  error is shown. The application does not change the system clock.
- Timed pauses retain their remaining duration after clock recovery, including
  across another restart. Pausing and stopping also handle a clock correction
  before the next tracking tick.
- Settings → Status & permissions now shows general tracker errors and the path
  to the recovery copy. The timeline reloads corrected history instead of keeping
  previously loaded future samples on screen.

This release also includes the backups, persistent timed pauses, quick tagging
and keyboard shortcuts prepared for [1.3.0](https://github.com/hlophlopgaming/DraugrTime/blob/v1.3.1/docs/releases/v1.3.0.md).

## Updating and limitations

- Quit the old instance through its tray, then start the new version. Your data
  remains in its existing local folder; the database format is unchanged.
- Clock-recovery copies contain the original full history. They are not removed
  by automatic-backup retention or later history deletion; remove them manually
  when no longer needed. Their location is shown for the current process.
- Backwards differences smaller than three seconds do not rewrite history;
  strict timestamp validation recovers as the clock catches up.
- Automated tests reproduce backwards jumps, restart recovery, pause persistence,
  failed backups and failed history writes. A real Windows → Linux reboot still
  needs manual verification.
- Windows installers are not publisher-signed; macOS bundles are not notarized.
